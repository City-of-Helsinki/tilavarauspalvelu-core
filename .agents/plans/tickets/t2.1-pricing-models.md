# T2.1 Add the pricing group, price component and price option models

Label: BE
Blocked by: T1.2

## Background

A reservation unit has one price at a time. The new model lets a reservation unit have several prices at once,
lets many reservation units share prices, and supports time-based prices, surcharges and discounts.

- A **pricing group** is a named set of prices. A reservation unit links to one pricing group at a time.
- A **price component** is one dated rule in a pricing group. The price of a reservation is the sum of the matching components.
- A **price option** is a label that the reserver selects, for example "Adults". One unit group owns it.

## Scope

Add these models with all fields and check constraints. Later tickets turn on the features.

- `PricingGroup`: `name` (translated), `unit_group` → UnitGroup, nullable.
  A group with a unit group is shared. A group with no unit group is a reservation unit's own group.
- `ReservationUnitPricingGroup`: `reservation_unit`, `pricing_group`, `begins: date`. Unique `(reservation_unit, begins)`.
  The active group is the row with the latest `begins` on or before the reservation start date.
- `PriceOption`: `name`, `description` (translated), `is_active`, `unit_group` → UnitGroup.
- `PriceComponent`:
  - `pricing_group`, `kind: BASE | SURCHARGE | ADJUSTMENT`, `valid_from: date`, `valid_until: date` (nullable, exclusive)
  - `price_option` → PriceOption, nullable (null means every option)
  - `amount: decimal` (gross € for BASE and SURCHARGE, a percentage for ADJUSTMENT)
  - `price_unit`, `tax_level`, `accounting` (nullable), `is_adjustable`, `can_apply_for_discount`,
    `material_price_description` (translated), `payment_type` (nullable)
  - Conditions, all nullable: `weekdays: int[]`, `time_begins`, `time_ends`, `dates_begin`, `dates_end` (month and day),
    `elapsed_from`, `elapsed_to`, `min_total_duration`, `max_total_duration`, `min_lead_time`, `max_lead_time`

Check constraints on PriceComponent:

| Field                        | BASE                           | SURCHARGE    | ADJUSTMENT |
|------------------------------|--------------------------------|--------------|------------|
| `price_unit`                 | required                       | required     | null       |
| `tax_level`                  | required                       | required     | null       |
| `accounting`                 | optional                       | optional     | null       |
| `is_adjustable`              | true                           | staff choose | false      |
| `can_apply_for_discount`     | staff choose                   | false        | false      |
| `material_price_description` | optional                       | optional     | empty      |
| `payment_type`               | required if `amount > 0`       | null         | null       |

Also: `valid_from < valid_until`, `time_begins < time_ends`, and the same for the other ranges.
`price_unit` is `FIXED` if a total duration condition is set.
A component can use a price option only if the option's unit group is the pricing group's unit group.

The validator rejects a value in a condition column, and the kinds SURCHARGE and ADJUSTMENT, until their tickets in group 8 are done.

## Acceptance criteria

- The models, constraints and Django admin views exist.
- Tests cover every check constraint.

# T2.3 Coverage validator for base components

Label: BE
Blocked by: T2.1

## Background

Each piece of a reservation must match exactly one base component, so that its price is always defined.
This is checked when staff save prices, not only when a reservation is made.

A price option is **offered** on a date if a base component for it is active on that date.
A base component with no option counts for every offered option.

## Scope

The validator checks all base components of one pricing group:

- From the earliest `valid_from` in the group onward, with no end, every date has at least one offered option.
  So the last base components have no `valid_until`.
- On every date where an option is offered, its base components cover all other axes exactly once:
  weekdays, time of day, recurring dates, elapsed time, total duration and lead time.
  This includes hours when the reservation unit is closed.
- All paid base components that are active on the same date have the same `payment_type`.

Method: all boundaries of the base components cut each axis into ranges. The ranges make a grid of cells.
Every cell must match exactly one base component for each offered option.

Also check on `ReservationUnitPricingGroup`: the pricing group has coverage from the row's `begins` date.

## Acceptance criteria

- Gaps and overlaps are reported with the components and the dates or times involved.
- Tests cover gaps in time, gaps in dates, overlaps, and conflicting payment types.

# T9.1 Shared pricing groups with unit group ownership

Label: BE
Blocked by: T2.1

## Background

Some organizations, such as the sports department, use the same prices in many reservation units.
They need to manage these prices in one place, and only their own staff should see and edit them.
UnitGroup already links units and gives permissions through `UnitRole.unit_groups`.

A pricing group with a unit group is **shared**. A group with no unit group is a reservation unit's **own** group.

## Scope

- GraphQL mutations to create, rename and delete shared pricing groups.
- A user can create and edit a shared pricing group if they have a role on its unit group.
- The permissions of an own group follow the unit of the reservation unit that uses it.
- A query that lists the shared groups that a reservation unit can use: groups whose unit group contains the reservation unit's unit.
- A mutation to schedule a reservation unit's pricing group (`ReservationUnitPricingGroup` with a `begins` date).
- To share an own group, staff set its unit group.

## Acceptance criteria

- Staff see and edit only the shared groups of their own unit groups.
- A reservation unit can be moved to a shared group from a future date.

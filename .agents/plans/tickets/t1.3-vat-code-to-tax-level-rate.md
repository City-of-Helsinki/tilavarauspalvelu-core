# T1.3 Move vat_code from PaymentAccounting to TaxLevelRate

Label: BE
Blocked by: T1.1, T1.6

## Background

The SAP VAT code is now on `PaymentAccounting`, and the VAT percentage comes from the pricing.
Nothing checks that they agree. The web shop gets the VAT code through the product accounting,
and the percentage through the order. If both come from one TaxLevelRate row, they cannot conflict in Varaamo.

## Scope

- Data migration: fill `TaxLevelRate.vat_code` from the accountings that use that percentage.
  If two accountings with the same percentage have different VAT codes, the migration stops and lists them.
- Remove `vat_code` from `PaymentAccounting`, its admin and its API.
- `refresh_reservation_unit_accounting` sends the VAT code of the current rate of the tax level.
- The VAT code is internal. The staff UI does not show it.

## Acceptance criteria

- The product accounting sent to the web shop has the VAT code of the tax level's current rate.
- The migration fails with a clear list if the data has conflicting VAT codes.

# T1.2 Use tax levels in reservation unit pricings

Label: BE
Blocked by: T1.1

## Background

`ReservationUnitPricing` links to `TaxPercentage`. A VAT change now needs a new pricing on every reservation unit.
These pricings have `is_activated_on_begins=True`, so they apply only to reservations made after the change date.
With tax levels, the rate changes in one place.

## Scope

- `ReservationUnitPricing` gets `tax_level` → TaxLevel. Migrate the value from `tax_percentage`.
- Pricings with `is_activated_on_begins=True` that only change the VAT: if the amount is the same as in the
  pricing before, remove the pricing and add a TaxLevelRate on its `begins` date.
- The GraphQL API reads and writes `taxLevel` instead of `taxPercentage`.
- Remove `is_activated_on_begins` from the API and the staff form input. Keep the column until the cleanup (T10.1).
- Remove the task `update_reservation_unit_pricings_tax_percentage` and the action `add_new_pricings_for_tax_percentage`.

## Acceptance criteria

- Every pricing has a tax level after the migration.
- A new tax rate changes the VAT of all pricings that use that tax level, with no new pricings.

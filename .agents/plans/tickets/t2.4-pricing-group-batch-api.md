# T2.4 Batch API to change the components of a pricing group

Label: BE
Blocked by: T2.3

## Background

A price change closes some components and adds others. The coverage check passes only when both are saved together.
So changes to a pricing group are saved as one batch.

## Scope

- A GraphQL mutation that takes a pricing group ID and a list of changed, new and deleted components.
- The backend merges the batch with the rest of the group from the database and validates the result.
- Errors can point to components that the user did not change.
- Edit rules:
  - Future components can be edited and deleted.
  - On an active component, only `valid_until` can change, and only to a future date.
  - Past components never change.

## Acceptance criteria

- A price change from a future date can be saved in one call.
- Changes to past components and to the price of active components are rejected.

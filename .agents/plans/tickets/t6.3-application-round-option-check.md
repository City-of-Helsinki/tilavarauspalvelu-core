# T6.3 Application round check for price options

Label: BE
Blocked by: T6.2, T2.3

## Background

An applicant selects one price option for an application section, and the section can include many reservation units.
The pricing groups of the units can be different, for example "Sports price category 1" and "Sports price category 3",
but they must offer the same options. The offered options come from the base components.

## Scope

- When a round is created or a unit is added, check that all its reservation units offer the same set of options on
  every date of the round's reservation period.
- A change of pricing group or of base components inside that period must keep those options offered.
  The coverage check and the `ReservationUnitPricingGroup` validator test this against open rounds.

## Acceptance criteria

- A round cannot include units whose groups offer different options.
- A price change that removes an option during an open round is rejected.

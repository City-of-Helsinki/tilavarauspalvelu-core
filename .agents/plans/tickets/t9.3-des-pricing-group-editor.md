# T9.3 Design the pricing group editor

Label: DES
Blocked by: none

## Background

Shared pricing groups hold the prices of many reservation units, for example "Sports price category 1".
A group has price components:

- **Base**: the rent, in €. Exactly one base component matches each moment, for each price option.
- **Surcharge**: an amount in € added to the rent, for example an evening supervision fee.
- **Adjustment**: a percentage, for example a summer discount of −20 %.

Each component has `valid_from` and `valid_until` dates, an optional price option, and optional conditions:
weekdays, time of day, recurring dates, elapsed time, total duration and lead time.
Active components can only be closed with a future end date. Past components never change.
The backend saves changes as a batch and returns errors for the whole group, also for components the user did not change.

Price options belong to a unit group, for example "Adults" or "Event A, juniors".

## Scope

- The editor for a pricing group and its components, including an action to change prices from a date.
- Price option management, on the same page or a separate one.
- A price preview: select an option, a date and a time range, and see the price lines, also with unsaved changes.
- The choice in the reservation unit form: "own pricing" or "shared pricing group".

## Acceptance criteria

- A design that the frontend team can implement in T9.4 to T9.7.
